### 静态化怎么做

`RebuildInk()` 先清空墨层与 `_strokes`，逐条从 `payload.path` 读 ISF 只填字典；`_inkFlattened` 为真时不往 `InkCanvas.Strokes` 加，改为 `RenderStaticInk()` 把 `StrokeCollection` 画进 `DrawingVisual`、`RenderTargetBitmap` 冻结成 `Image` 放进 `_plane`。新笔迹仍走 `CommitStroke` → 墨层，`MaybeFlattenInk()` 在 `CommitStroke` 末尾判断阈值。`FlattenInk()` 可手动触发（探针用）。

阈值来自 plan §4.8：`FlattenStrokeLimit = 500`、`FlattenVertexLimit = 2000`，判断用 `>`（正好 500 笔不触发，501 才触发）。

### 清理为什么只挪不删

D23/D27 欠的是「删除图元时 `.isf`/图片不删，撤销能把它们找回来」。清理若直接 `File.Delete`，一次判断失误就是永久丢文件；§3 铁律与「不可逆操作前先备份」都指向保守。所以 `AssetCleanup` 把孤儿文件 `File.Move` 到 `trash/assets-<yyyyMMdd-HHmmss>/`，重名加 `-1`/`-2`；**没给回收目录时一个文件都不动**；`*.tmp` 永不碰。

### 50 图元 + 500 笔的帧成本（代理测量）

```
PERF 未静态化 50 图元 + 500 笔：帧均 59.8 ms ≈ 17 fps
PERF 静态化后   50 图元 + 500 笔：帧均 105.2 ms ≈ 10 fps（提速 0.6×）
```

**这不是 App 的帧率。** 这里用 `RenderTargetBitmap.Render()` 强制走 CPU 软件光栅，一张 1800×1000 的 Pbgra32 位图在软件路径上比 500 条矢量笔画更贵，所以静态化后反而慢。真实 App 由 WPF 合成器（GPU）出帧，笔迹静态化的收益在「墨层命中测试与逐帧重绘的 CPU 开销」上，软件光栅测不出来。

结论：这条测量**只能证明静态化没破坏模型与渲染路径**（位图层真的出现了、笔画没丢、重开能读回），不能作为 V-12 的 ≥55 fps 证据。V-12 的三条数字记为 PENDING-HUMAN，复测命令见 §4。

## 4. 怎么在真机上补测 V-12 的前两条

必须**先退出**正在跑的 Wantodo（PID 10756，单实例 Mutex `Local\Wantodo.SingleInstance`），否则新实例启动即退出（本步已实测：`alive=False exit=0`，日志目录都没建）。

```powershell
# 1) 退出正在运行的实例（用户自己操作，别用 taskkill 硬杀）
# 2) 用 portable 副本跑，绝不碰真实数据
$env:DOTNET_ROOT="$env:LOCALAPPDATA\Microsoft\dotnet"; $env:PATH="$env:DOTNET_ROOT;$env:PATH"
Measure-Command { & .\publish\0.7.0-test\Wantodo.exe }   # 首帧时间见 AppLog「启动 … ms」
Get-Content .\publish\0.7.0-test\data\logs\*.log -Tail 20
# 日志里有「启动 … 内存 WS=… private=… 线程=…」一行（App.xaml.cs 的启动日志）
```

判据：日志里 `启动 … ms` ≤ 1153，`private=` ≤ 105.1 MB。首帧指进程启动到主窗口可交互，取 AppLog 里的启动耗时；三次数取中位。

- 没做笔迹位图的**分层缓存**（视口平移时整张位图重画；超大画布会吃显存，等真机测出问题再说）。
- 没做图片缩略图（Q4 明确「不生成缩略图」）。
- 没改红线、没放宽 `V-12` 阈值、没把 PENDING 写成通过。
- 没动 `E:\Wantodo\board\`（只读；全程 Length 4834 / mtime 2026-11-15 22:03:50 未变）。
