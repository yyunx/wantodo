# P0.5 液态玻璃探针（Mica 三问）

跑法：`spike/MicaProbe`（独立 WPF exe，不进 `Wantodo.slnx`），每轮启动后由 pwsh 按日志里的窗口矩形截屏。
产品窗口因单实例 Mutex 无法在真机并行启动，所以探针是唯一能带界面取证的通道。

- 系统：Windows 11 `10.0.26200`，150% DPI（760×320 DIP 窗口 → 1140×480 物理像素）
- 桌面层拓扑：`SHELLDLL_DefView` 直接在 `Progman` 下（探针初版只找顶层 WorkerW 会找不到，与 `docs/verify/phase0.md` 的结论一致）
- 日志：`docs/verify/0.7.0/probe-mica.log`；截图：本文引用的 `probe-*.png`

## 三问结论（先给答案）

| # | 问题 | 结论 | 证据 |
|---|---|---|---|
| 1 | 禁 `AllowsTransparency` 时怎么让 Mica 透出来 | **必须** `WindowChrome.GlassFrameThickness=-1` + `Window.Background=null`；只调 DWM 属性完全不可见 | 探针 A/B/C |
| 2 | 贴桌面层（owner=Progman + `WS_EX_NOACTIVATE`）的窗口 Mica 是否生效 | **生效**，与普通窗口逐字节相同的画面 | 探针 D |
| 3 | 收起态 12 DIP 条要不要材质、切换是否闪 | 条带能出材质（DWM 调用成功、截图非黑）；**闪不闪无法自动判定** → PENDING-HUMAN | 探针 F |

## 探针 A：只调 DWM，不装 WindowChrome

命令：`MicaProbe.exe --mode normal --material mica`

```
OS build=10.0.26200.0 (Win11)
DwmExtendFrameIntoClientArea hr=0x00000000
material: DWMWA_SYSTEMBACKDROP_TYPE=DWMSBT_MAINWINDOW hr=0x00000000 → 已请求
```

对照组 `--material none`：两张截图 **逐像素完全相同**（7,595 个采样点 `avgAbsDiff=0`，中心都是 `rgb(20,21,29)`）。
`probe-normal-mica.png` / `probe-normal-none.png`。

结论：`DwmSetWindowAttribute(38, 2)` 返回 `S_OK` 也只说明 DWM 收下了请求；WPF 客户区是不透明像素，
材质被整块盖住。**hr=0 不等于看得见。**

## 探针 B：`Background=null` 但不装 WindowChrome

`--bgnull`：中心 `rgb(20,21,29)`，与探针 A 一样，材质仍不可见（`probe-bgnull-mica.png`）。

## 探针 C：`WindowChrome.GlassFrameThickness=-1` + `Background=null`

`--chrome`：

| 变体 | 中心像素 | 说明 |
|---|---|---|
| chrome + mica | `rgb(76,77,85)` | 均匀单色（180 个采样点只有 1 种颜色） |
| chrome + none | `rgb(25,26,34)` | 纯色内容层 |

两图 `avgAbsDiff=142.16`、`maxDiff=153`（7,595 点）→ 材质确实透上来了（`probe-chrome-mica.png` / `probe-chrome-none.png`）。

补充对照：在探测窗后面铺一块纯洋红窗口（`--mode backdrop`），画面 **逐字节不变**
（`probe-backdrop-mica.png` 与 `probe-chrome-mica.png` 同一个 sha256），说明透出的不是「背后窗口」，
而是 Mica 采样的壁纸——这正是 Mica 的定义（只采样壁纸、忽略其它窗口）。

## 探针 D：桌面层窗口

`--mode desktop`：`owner=WorkerW 0x101EA`，并置 `WS_EX_NOACTIVATE`。截图与普通窗口 **同一个 sha256**
（`probe-desktop-mica.png`）→ 桌面层 owner 关系不会让 DWM 停止画材质。

## 探针 E：玻璃区会不会吞鼠标

`--mode click` 在玻璃窗口里放一个按钮，用 `SetCursorPos` + `mouse_event` 模拟真实左键点击：

```
[输入] 按钮点击生效 ✓
[输入] 已在 1298,208 模拟点击
```

结论：`GlassFrameThickness=-1` 且 `CaptionHeight=0`、`ResizeBorderThickness=0` 时，客户区控件照常收到
点击，不会被当成标题栏拖拽区。

## 探针 F：12 DIP 收起条

`--mode collapsed`：先渲染 320 DIP，等 1.2 s，压到 12 DIP（150% DPI 下 18 px），再回 320 DIP。

```
rendered:  rect=710,60,1850,540 size=1140x480
collapsed: rect=710,60,1850,78  size=1140x18
collapse+expand 总耗时 2456 ms
expanded-again: rect=710,60,1850,540 size=1140x480
```

`probe-collapsed-strip.png`（1140×18）显示条带确实画出了内容，不是全黑；DWM 材质调用仍是 `hr=0`。

PENDING-HUMAN：条带切换时是否可见闪白/闪黑 —— 截图只能证明「某一帧不是黑的」，不能证明连续帧不闪。
判据见 `p0.5.md`。

## 对实现的硬约束（已写进代码注释）

1. 窗口必须 `WindowChrome.GlassFrameThickness=-1` + `Background=null`，否则材质永远看不见；
2. 因此内容层必须自己带半透明底色（L1 α0.72 / L2 α0.86），否则会直接透出桌面文字；
3. 材质不可用时必须把背景恢复成不透明纯色（否则整窗漏底），并记 WARN。
