## 3. 验收对照

| 验收 | 结论 | 依据 |
|---|---|---|
| V-06 无铬图片：无外框、选中才出手柄 | 部分 PASS（代码层） | 探针断言未选中时图片视觉是 `Thickness(0)` 的 `Border`，选中时才 1 px `Accent`；「看起来是否无框」仍需人眼 → 见 §4 |
| V-07 剪贴板两形态都生成对象 | PASS（逻辑层） | `FreeformBoard.Paste()` 位图分支走 `PngBitmapEncoder` → 临时文件 → `AddImageObject`；文件分支走 `DataFormats` 文件列表；两分支最终同一入口，探针断言同图两次只留一个资产文件 |
| 资产 sha256 前 16 位命名、同图去重 | PASS | `ImageAssetTests.Import_WritesUnderCanvasImagesWithHashName` / `Import_SameContentTwice_KeepsOneFile` + 探针第 ⑨ 段 |
| `data.json` 不含 base64，只存相对路径 | PASS | `RelativePath` 形如 `canvas-images/<hash>.png`，探针断言非绝对路径；模型只写 `payload.path` |
| 单张 ≤20 MB，超限拒绝并提示 | PASS | `Import_RejectsOversizeFile` 断言错误文案含「超过上限」，调用方 `AppLog.Warn` |
| 总量 >200 MB 提示 | PASS（逻辑层） | `Import_ReportsTotalWarningPastThreshold`；真实触发需塞 200 MB 资产，不做 |
| 图片只存在于自由表面 | PASS | 结构化面 `AddImage` 已删除、白名单已删，`TryPaste`/`OnDrop` 只抛事件；探针用反射守住 |
| 按显示尺寸解码 | 部分 PASS | `LoadBitmap` 已设 `DecodePixelWidth = item.W`；内存增量 ≤3 MB 属 P2.2 性能项，本步不测 |

## 5. 本步刻意没做

- 不做缩略图生成（Q4 裁决：原图 + `DecodePixelWidth`，不生成第二份副本）。
- 不清理孤儿资产：删掉图片对象后 `canvas-images/<hash>.png` 仍留着（撤销要能找回），清理留 P2.2。
- 不做 50 张图的内存与首帧复测（P2.2 性能验收一起测）。
- 旧数据里已有的结构化图片卡仍能渲染（兼容），但不会再新增。
