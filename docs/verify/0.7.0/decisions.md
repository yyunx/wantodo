# 0.7.0 夜间执行：我替你做的决定

按提示词 A2 记录：凡是计划书未逐字规定、由执行者按推荐值自决的点。用户的 §1 裁决（Q1–Q10、A1–A8）不在此列。

| # | 决策点 | 选定 | 理由 | 改回成本 |
|---|---|---|---|---|
| D1 | `CanvasDocument` 版本号 | 新结构用 `2`，旧 `canvas.json` 视为 `1` | 旧文件已占用 1；用 `Version < 2` 判定旧结构，迁移路径无歧义 | 低：改常量 + 一处判断 |
| D2 | 图元（`Objects`）与卡片（`Cards`）的分界 | `kind=image` 进 `Objects`，其余（note/todo/timer/link）进 `Cards` | 图片属于自由表面素材，卡片属于结构化表面投影；P1.3 起笔迹/图形也进 `Objects` | 中：影响 P1.2/P1.3 数据形态 |
| D3 | 旧画布导入时机 | `Load()` 三分支都尝试，导入成功立即 `Save` | 避免每次启动重复导入；坏文件时也不会把旧画布丢掉 | 低 |
| D4 | 两边都有画布内容时 | 以 `data.json` 为准，旧文件改名保留，记 WARN | Q1 已裁决「以 data.json 为准」（迁移表第 9 行） | 低 |
| D5 | 升级前备份名 | `data.json.pre-070.bak`（只生成一次，存在跳过） | 计划书 V-02 明文要求该文件名 | 低 |
| D6 | `Items` 兼容别名 | 保留 `[JsonIgnore] Items => Cards`，P0.3 删 | 让 `CanvasBoard` 在 P0.1 不必同步大改，减少夹带 | 低：P0.3 一并清理 |
| D7 | App 层剩余裸 hex 的处理 | 允许三类例外并登记：`App.xaml` 的默认回退刷子、`ThemeColorPicker` 的 HSV 渐变、`ThemeStyles.xaml` 的装饰纹理 | 前两类是「主题应用前」的兜底与选择器自身的画布，第三类是几何纹理不是主题色；P2.1 若有余力再把纹理改成令牌 | 低：换成令牌需要新增 3 个资源键 |
| D8 | 迁移后是否立即落盘 | 是：`Load()` 里 `upgraded` 为真就 `Save` | V-02 要求「打开一次后 `data.json` 里有 paletteId」；不落盘则每次启动都重新迁移、诊断反复 | 低 |
| D9 | 旧 `formId` 的落点 | 全部折成 `liquidGlass`，`solid` 只保留常量不启用 | 计划书 §1.4 迁移表：formId 丢弃 + WARN；本期只交付一种材质 | 中：启用 solid 要补设置项与色板取值 |
| D10 | `CanvasStore` 的去留 | 整个类删除，`CanvasBoard` 改成接收 `Action<CanvasDocument>` 回调 | 单文件后独立读写器只会诱发「又在写 canvas.json」；回调让宿主自己决定何时合并保存（600 ms 去抖） | 低：类是自包含的，可从 git 历史取回 |
| D11 | 撤销时 `_document` 被整份替换 | 回调里把新实例写回 `Board.Canvas` 再请求保存 | 不做就地拷贝，避免「两份文档实例」；代价是 `Board.Canvas` 引用会变，凡缓存旧引用的地方都要重新取 | 低 |
| D12 | `DataPaths.CanvasFile` | 删除，并加单测断言该属性不存在 | 光删调用点不够，留着属性迟早被重新用上 | 低 |
| D13 | 自由表面宿主在 P0.4 的渲染范围 | 只渲染图片与文本两种图元，笔迹/图形先画边框占位 | 笔迹/图形属 P1.2；先留宿主与数据通路，避免 P0 就长出一个半成品绘图工具 | 低 |
| D14 | 分段控件里 `＋` 的行为 | 保留按钮（Q2 要求），点击只记日志 + tooltip；不新建表面 | 本期只有两个表面，凭空造第三个会让 `Cards`/`Objects` 的「表面」语义不清 | 低 |
| D15 | 表面切换是否重建控件 | 不重建，两个宿主常驻，只切 `Visibility` | V-04 要求「不闪白、句柄不变」；重建会让滚动位置与撤销栈一起丢 | 中：改回重建要处理状态迁移 |
| D16 | 材质在 P0.5 的作用范围 | 只给 `SettingsWindow`（Win11 上真实 Mica）；`TopPanelWindow` 本步不启用 | 面板贴桌面层且自己管拖拽/缩放/命中测试，材质透出后的观感（12 DIP 条、DWM 圆角、卡片对比度）必须人眼看过；验收 V-11 指定的就是设置页 | 低：面板加两行 `GlassSurface.Prepare/TryApply` 即可，P2.1 再做 |
| D17 | 让 Mica 透出的前置条件 | 必须 `WindowChrome.GlassFrameThickness=-1` + `Window.Background=null`，内容层自己带 α0.72/α0.86 底色 | 探针实测：只调 `DwmSetWindowAttribute` 时 mica 与 none 逐像素相同（hr=0 但不可见）；背景置空后可见，且控件照常可点 | 低：条件集中在 `GlassSurface` |
| D18 | 材质不可用时的画面 | 内容层退回不透明 `WindowBackground`/`CardBackground`，并记 WARN | 半透明内容叠在不透明窗口上会被误当成玻璃；探针也不支持 Win10 Acrylic（未文档化 API、无真机） | 低 |
| D19 | 自由表面的手势入口形态 | `FreeformBoard.PointerDown/PointerMove/PointerUp` 公开，鼠标事件只做捕获与转发 | 「平移不与框选串」这类互斥手势，靠人眼看十几次不如让探针在真实控件上打一遍；公开入口也让 P1.2 的绘图工具复用同一套坐标换算 | 低：三个方法是薄转发 |
| D20 | 缩放与滚轮的方向约定 | 滚轮向上放大、向下缩小，锚点=指针；缩放工具左键放大、Shift+左键缩小；倍率固定 1.25 | 与浏览器/看图软件的习惯一致；固定倍率让「按 N 次到端点」可测，不做平滑惯性以免和触摸板双击冲突 | 低：倍率与方向各是一行常量 |
| D21 | 创建类工具在 P1.1 的行为 | 点下去只记 `[画布] 工具 X 的创建行为在 P1.2 接入`，不产图元 | P1.1 的验收集中在「工具可选、互斥、缩放平移正确」；若提前接创建，会顺带引进撤销、落盘时机、资产目录三件 P1.2/P1.3 的事 | 低：接创建时替换一条 switch 分支 |
| D22 | 撤销的存储单位 | 每个表面一份「该表面卡片 + 图元的 JSON 快照」，深度 50，只在内存 | 计划书 §4.8 举例的是操作闭包，但闭包要为正反向各写一遍逆操作，出错面大且难断言；快照让 V-13 的「A 面 3 步 / B 面 2 步」可以直接用字符串比较验证。50 步 × 单表面内容，实测内存可忽略（P2.2 若超标再换闭包） | 中：换闭包要重写 `SurfaceUndo` 与两处 `PushUndo` |
| D23 | 笔迹的落盘与删除 | 一笔一个 `board/ink/<objectId>.isf`；模型里只留 `payload.path`；删除图元暂不删 `.isf`，撤销恢复靠重新读文件 | ISF 是 WPF 原生可序列化的，二进制不进 `data.json`（V-06 要求文件里没有 base64）；先不删文件是为了「撤销能把笔画找回来」，孤儿文件由 P2.2 的清理做 | 低：删除钩子加一行即可 |
| D24 | 图形（矩形/线/箭头）的画法 | 用绝对画布坐标画，不套 `Wrap` 的「矩形框 + 内容」；箭头用 `StreamGeometry` 画线 + 两条回折头；选中高亮走 `StrokeThickness` 2→3 与令牌色 | 线段/箭头用矩形框表示会丢掉端点与朝向；绝对坐标也让缩放、命中测试与文本/图片走同一套换算 | 低：`BuildShape` 是独立方法 |
| D25 | 图片资产的命名与引用 | 原图存 `board/canvas-images/<sha256 前 16 位>.<ext>`，模型只存相对路径 `canvas-images/<hash>.<ext>` | 内容寻址天然去重（同图粘贴两次只留一份）；相对路径让整个数据目录可整体搬迁；前 16 位（64 bit）在本项目量级不存在碰撞风险 | 低：`ImageAssets.ShortHash` 一处 |
| D26 | 剪贴板位图的落盘路径 | 先编码到 `%TEMP%\wantodo-paste-<guid>.png`，再交给 `ImageAssets.Import`，`finally` 删除临时文件 | 直接写资产目录会留下时间戳命名的重复文件（sha256 命名就被绕过了）；先落临时文件再入册，编码逻辑只有一份，也不需要把剪贴板位图转成 `byte[]` 手工算 hash | 低：一处 `try/finally` |
| D27 | 结构化表面的图片入口 | 工具栏图片按钮 = 切到自由表面 + 在视口中心落位；`Ctrl+V`/拖放只抛 `ImagePasteRequested`/`ImageDropRequested` 事件由宿主转交；`CanvasBoard.AddImage` 删除，旧结构化图片卡只为兼容渲染 | §4.7 明写「图片只存在于自由表面」，留着 `AddImage` 迟早被再次调用（探针用反射守住「方法不存在」）；事件让宿主控制「切面 → 落位」的先后，控件不依赖窗口 | 中：恢复结构化图片卡要加回方法、白名单与落位逻辑 |
| D28 | 计时卡的状态字段 | 新增 `payload.state`（`idle/configured/running/paused/done`）；老卡片没有该键时由 `TimerStates.Infer` 按 `startedAt`/`elapsed`/`fired` 反推 | 硬迁移要遍历所有卡重写 payload，且 0.6.0 老数据一旦被误读就会「一打开就在跑」；反推是纯函数、可单测，也让老卡打开后按钮文案正确 | 低：删掉 `Infer` 的两个兜底分支即可 |
| D29 | 番茄钟计划的序列化 | `"<组数>|<repeat>:<focus秒>:<break秒>;..."` 压进 `payload.plan` 的单个字符串；时间轴只在 Core 的 `PomodoroPlan.At()` 里算 | 计划最多 4 段，JSON 字符串化会让 payload 变成嵌套对象、与「payload 只放字符串」的既有约定冲突；紧凑格式可读、可测，坏数据统一回默认 | 低：`ToKey`/`Parse` 成对替换 |
| D30 | 待办卡的刷新方式 | 每秒一次 `Tick` 调用投影闭包，闭包先比较「栏目 id + 条数 + 完成位 + 文本」签名，变过才重建行；新增/勾选后立即强制刷新 | 桌面与画板是两个控件、共享同一个 `NoteColumn`，没有通知机制，轮询是最小改动；签名比较让「没变化」时不重画，避免滚动位置每秒跳回顶部 | 中：要做真正的观察者需给 `NoteColumn` 加事件并全量接线 |
| D31 | 改名入口 | 卡片标题是静态 `TextBlock`，只由「双击标题」或 `F2` 触发改名；拖动要超过 4 DIP 才开始；进入改名不写模型，`Enter`/失焦提交、`Esc` 取消 | 0.6.0 的标题是常驻可编辑 `TextBox`，单击就进编辑，和拖动抢事件；拆成「静态文本 + 显式改名」后 V-15 的「单击 100 次」在结构上就不可能进编辑 | 低：标题槽位是独立方法 |
| D32 | 简洁版与自定义分段的互转 | 简洁版始终写成「一段重复 N 组」；已有自定义时切回简洁版先弹 `MessageBox` 二次确认，确认后压成一段；自定义最多 4 段 | 计划书要求「简洁版写回压成单段」「二次确认」；用系统 `MessageBox` 而不是自绘对话框，是因为这段流程只在设置计时时走一次，不值得再引一套窗口样式 | 低：确认逻辑集中在一个分支 |
| D33 | 面板 `TopPanelWindow` 启用材质 | 构造里 `GlassSurface.Prepare(this)`，`OnSourceInitialized` 里 `TryApply`；可用性完全由启动时的 `ThemeService.Apply` 决定 | D16 欠账到期：矩阵 #3/#4/#23 都写「面板独立窗口 + SurfaceCard α0.86」，不做的话「液态玻璃」只存在于设置页。改回成本极低：删两行调用即回到纯色 | 低：两行调用 |
| D34 | 图片卡不挂右键菜单 | 结构化卡片（记事/待办/计时/链接）右击出「改名/置顶/删除」；图片沿用 P1.3 的「双击 / 右击 = 打开图片」 | 图片是无铬对象，双击打开是 P1.3 定的手势；再挂菜单会和打开抢同一个 `MouseRightButtonUp`，要么丢打开要么丢菜单 | 低：给 `BuildImageCard` 加一行 |
| D35 | 空状态是否带引导按钮 | 只出一句 `TextMuted` 文案，不放 `AccentSoft` 引导按钮 | 引导按钮要么占第三行（把工具栏从 ≤88 DIP 顶出去），要么挤进画布中央挡住框选；矩阵只要求「一句文案 + 引导按钮」二选一的可读性，文案已够 | 低：两处 `TextBlock` 旁边加 Button |
| D36 | 笔迹静态化阈值与测量方式 | `FlattenStrokeLimit = 500`、`FlattenVertexLimit = 2000`，判断用 `>`；静态化后新笔迹仍进墨层，旧笔画走一张冻结位图 | 阈值来自 plan §4.8；`>` 保证「正好 500 笔」不触发、第 501 笔触发。探针用 `RenderTargetBitmap` 测的是 CPU 软件光栅（50 图元 + 500 笔：59.8 ms → 105.2 ms），**位图在软件路径更贵**，所以这条数字不能当 V-12 的帧率证据，V-12 仍记 PENDING-HUMAN | 低：删掉 `MaybeFlattenInk()` 调用即回到全矢量 |
| D37 | 孤儿资产怎么处理 | 启动时 `AssetCleanup.Run()` 把没被 `payload.path` 引用的 `board/ink/*.isf`、`board/canvas-images/*` **挪进** `trash/assets-<yyyyMMdd-HHmmss>/`，不删；没给回收目录时一个都不动；`*.tmp` 永不碰 | D23/D27 欠的是「删图元时文件不删」；直接删一次判断失误就永久丢文件，与 §3 铁律和「不可逆操作前先备份」冲突。挪进回收目录既能止住无限堆积，又能翻回来。代价是 `trash/` 会缓慢长大，P2.3 的 release notes 写清清理方式 | 低：把 `File.Move` 换回 `File.Delete` 即可 |
| D38 | 包体积红线与减重 | 红线 229,376 B 不动；本步只做零成本减重（删零引用的 `ThemeColorPicker`，zip −2,739 B）；净超 55,955 B 写进 release notes | Q10 写明「不许偷改红线，还不上就写进 release notes」。0.7.0 净增来自画布两个控件（约 2,300 行）与 7 套色板，压缩收益最大的动作（拆资源字典、删旧链接卡渲染）风险高于今夜剩余时间能验的范围 | 低：红线是文档数字，改回去改一行；减重是后续独立任务 |
