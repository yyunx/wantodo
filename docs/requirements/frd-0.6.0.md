# 功能需求文档 0.6.0

> 覆盖 0.6.0 的需求全集：一次写清，不代表一次做完。阶段映射见 `docs/plan.md`（Phase 11 起），
> 视觉与交互细节见 `docs/design/visual-0.6.0.md`。字段：每条 8 行以内，缺字段即不合格。

## 0. 判定口径

- **默认开关**：写「开 / 关 / 无（缺陷修复）」。用户不做任何设置时的行为。
- **体积与性能**：给估计值 + 测量点；数字以 `dotnet publish` 的 zip 字节、`App.xaml.cs:92-105`
  的首帧日志、稳定 60 s 的 private 为准，测法见 `docs/verify/phase3.md`。
- **砍掉条件**：写触发条件，不写「以后再说」；砍掉后该条要回到本文并标注「未做」。
- **优先级**：P0 不做完不发版；P1 发版前必做；P2 目标版本内做；P3 可推迟，推迟必须进 `docs/plan.md` 未排期区。

## 1. 需求全集

### B1 随心记光标跳转（P0）

- 用户故事：我在正文中间改字，停手自动保存后光标还在原处，不用再点回去。
- 交互步骤：1 打开随心记选一条 → 2 把光标放到中间 → 3 连续输入 20 字 → 4 停手等保存 → 5 光标与滚动位置不变。
- 数据模型：无变更。
- 默认开关：无（缺陷修复）。
- 体积/性能：0 KB；不改启动与内存路径；不新增文件。
- 验收：500 字文档中间输入 20 字，停手 3 s 后光标在原字符后、无滚动、无丢字；外部编辑器改动仍 ≤2.5 s 刷新。
- 砍掉条件：不砍（P0 回归；修不好则 0.6.0 不发版）。

### S1 体积 / 启动 / 内存基线（P0）

- 用户故事：每次改动后我能用同一套数字判断「变重了没有」。
- 交互步骤：无（工程任务）→ 出两种包 → 冷启动 5 次 → 静置 60 s → 记录三组数。
- 数据模型：无变更（只写 `docs/verify/baseline-0.6.0.md`）。
- 默认开关：无。
- 体积/性能：不新增代码；产出 3 个数 + 命令原文；对照 0.5.0（首帧中位 811 ms、private 73–86 MB、
  zip 63,869,489 B / 196,936 B）。
- 验收：文档含 zip 字节、5 次首帧原值 + 中位、private 中位，且写明测量条件（DPI、显示器数、冷/热）。
- 砍掉条件：不砍（后续所有体积结论都依赖它）。

### D1 0.5.0 遗留收口（P1）

- 用户故事：0.5.0 的发布说明存在，两条一直没勾的验收有结论，不留悬案。
- 交互步骤：1 写 `docs/release-0.5.0.md` → 2 在 `phase10.md` 写两条肉眼项步骤 → 3 用户实测 → 4 据实勾选或记失败。
- 数据模型：无变更。
- 默认开关：无。
- 体积/性能：0 KB；只改 docs。
- 验收：`docs/release-0.5.0.md` 四节齐全；`docs/plan.md:467-468` 不再是「待确认」。
- 砍掉条件：用户坚持不发 0.5.0 说明时，只保留肉眼项结论。

### T1 主题：令牌、预设与全色自定义（P2）

- 用户故事：我能选整套配色，也能自己挑背景和强调色，且无论怎么选文字都看得清。
- 交互步骤：1 设置 → 外观 → 2 选预设或「自定义…」→ 3 取色器里选背景 / 强调色 → 4 看预览与对比度读数 → 5 关闭即生效。
- 数据模型：`Board.Theme` 取值扩为 `Dark|Light|System|Sakura|Cyber|Comic|Custom`；新增可空
  `CustomBackground`、`CustomAccent`；`Version` 仍为 2；未知值回退深色。
- 默认开关：新装 `Dark`；老用户保留原值；「自定义」与「跟随系统」默认关（选预设后自动关跟随系统）。
- 体积/性能：二进制 +≤50 KB、代码 +≈620 行（含测试）、0 新依赖、0 图片；切换不重建窗口、≤16 ms；内存 +≤2 MB。
- 验收：5 套预设与自定义组合全部满足 正文 ≥7:1、次要/弱化 ≥4.5:1、强调块文字 ≥4.5:1；重启后保持。
- 砍掉条件：取色器工作量超 2 天 → 只留 5 套预设 + hex 单输入框（砍色相条与 S/V 方块）。

### S2 轻量化（P2）

- 用户故事：同一功能下包更小、启动更快，而且每步省了多少有账可查。
- 交互步骤：无（工程任务）→ 以 S1 基线为起点 → 每次只做一项瘦身 → 记录字节差。
- 数据模型：无变更。
- 默认开关：无。
- 体积/性能：目标值由用户给定（当前未定）；每项记录「改前 / 改后 zip 字节、首帧、private」。
- 验收：给出目标值与达标结论；每项瘦身有独立 commit 与数字。
- 砍掉条件：用户未给目标字节数时不排期（已进 `docs/plan.md` 未排期区）。

### K1 超链接与附件（P3）

- 用户故事：条目里能放链接 / 附件，点一下能打开。
- 交互步骤：1 选中文字或拖文件进条目 → 2 选择「插入链接 / 附件」→ 3 显示图标与文件名 → 4 点击用系统默认程序打开。
- 数据模型：`Note` 新增 `Links`（`[{text,url}]`）与 `Attachments`（`[{name,path}]`），均可空；随 board 存。
- 默认开关：关（能力存在，但不在主界面显示按钮，避免界面变复杂）。
- 体积/性能：+≈15 KB；打开链接走 `ShellExecute`，无轮询；附件只存路径，不复制文件。
- 验收：链接可点开；路径失效时显示「文件已移动」而不是静默失败；不复制用户文件。
- 砍掉条件：用户要求「附件必须随数据根迁移」时，需先做复制策略与去重，否则不排期。

### K2 键盘补齐：`Ctrl+N` / `Esc`（P3）

- 用户故事：手不离键盘也能新建和退出。
- 交互步骤：1 主窗口按 `Ctrl+N` → 2 当前栏末尾出现新条目并进入编辑 → 3 `Esc` 取消编辑或关窗。
- 数据模型：无变更。
- 默认开关：开（纯键盘，不增加界面）。
- 体积/性能：+≈2 KB；无启动影响。
- 验收：`Ctrl+N` 在主窗口任意焦点下生效；`Esc` 在 5 个已有窗口行为不回退（`BlockersWindow.xaml.cs:181` 等）。
- 砍掉条件：grep 发现与现有输入法 / 编辑器冲突，改为 `Ctrl+Shift+N` 并记 `decisions.md`。

### U1 顶边下拉面板（P3）

- 用户故事：鼠标撞到屏幕顶边就能把便签拉下来看，不用切窗口。
- 交互步骤：1 鼠标撞顶停留 120 ms → 2 出现把手 → 3 按住往下拖 → 4 松手展开/收回 → 5 `Esc` 或点外部收回。
- 数据模型：`Board` 新增 `ShowTopPanel`（bool，默认 false）、`PanelHeight`（double，默认 320）。
- 默认开关：关。
- 体积/性能：+≤60 KB；面板懒加载，常态 0 内存；空闲 CPU 0；展开时 private +≤6 MB。
- 验收：撞顶出把手、拖过 40% 展开；面板与桌面窗口同一份 `data.json` 双向 1 s 内同步且互不覆盖；关开关后无钩子无窗口。
- 砍掉条件：Phase 16 探针证明热区与系统「贴边最大化」无法共存 → 改托盘快捷键呼出，形态保留。

### U2 面板形态 B：自由画布（P3）

- 用户故事：面板里能像 scratch 一样随手放东西，而不是只有固定两栏。
- 交互步骤：1 下拉面板切到「自由画布」→ 2 双击空白处新建文本块 → 3 拖动摆放 → 4 关闭自动保存。
- 数据模型：新文档 `board/canvas.json`，与 `Board` 分离；不复用 `LayoutNode`。
- 默认开关：关（且需 U1 完成）。
- 体积/性能：估 +≈120 KB；不加载时不建对象；不参与启动。
- 验收：位置、尺寸、文字重启后恢复；与 Board 数据互不影响；坏文件回退空画布并记日志。
- 砍掉条件：U1 形态 A 未通过验收、或与 `LayoutNode` 差异表说明收益不足 → 不做。

### U3 日历视图（P3）

- 用户故事：按日期看条目，知道哪天有什么。
- 交互步骤：1 顶栏「日历」→ 2 月视图 → 3 点某天看条目 → 4 可把条目拖到另一天。
- 数据模型：只复用 `CreatedAt` / `CompletedAt`，不新建时间模型；若需「计划日期」则新增可空 `DueAt`（禁止两套）。
- 默认开关：关。
- 体积/性能：+≈25 KB；按月渲染，不预生成全年。
- 验收：条目落在正确日期；跨月切换无卡顿（<100 ms）；无 `DueAt` 时按创建日显示。
- 砍掉条件：用户要求「拖到某天 = 改创建时间」则否决——创建时间不可变，需先定 `DueAt`。

### F1 问候语 + 页脚场景（P3）

- 用户故事：页面底部有点生气，但不打扰。
- 交互步骤：1 打开主窗口 → 2 页脚按时间段显示一句问候 → 3 完成条目时按场景播一次短动效。
- 数据模型：`Board` 新增 `FooterScene`（string，默认 `off`）；不存动画状态。
- 默认开关：关。
- 体积/性能：+≤30 KB；矢量优先，禁止图片序列；动画只用 XAML `Storyboard`。
- 验收：时段映射正确（早/午/晚/夜）；关闭后功能完整；完成多条目时动效合并不排队。
- 砍掉条件：单场景超过 30 KB 或超过 1 天 → 只做问候语，页脚场景不做。

### F2 task-nest 式字段（P3）

- 用户故事：条目除了完成，还能有「进行中 / 搁置」这样的状态。
- 交互步骤：1 条目右键 → 2 改状态 → 3 列表按状态分组显示 → 4 状态与「完成」不冲突。
- 数据模型：`Note` 新增 `State`（枚举字符串，默认 `Todo`）；`Completed` 保留为派生视图，避免两套真值。
- 默认开关：关。
- 体积/性能：+≈10 KB；分组只在渲染层，不改存储结构。
- 验收：四态切换后重启保持；0.5.0 文件升级无损；`Completed=true` 与 `State=Done` 始终一致（单测）。
- 砍掉条件：无法证明「单一真值」→ 整条不做，宁可没有状态。

## 2. 非目标（0.6.0 明确不做）

- 云同步 / 账号 / 多人协作；移动端。
- 富文本、Markdown 渲染、图片内嵌正文。
- 第三方 UI / 动效 / 取色库；换 UI 框架。
- 插件系统、脚本能力、主题市场。
- 改数据根指针机制、改 `.lock` 语义、改 schema 版本号（仍为 2）。
- 全屏游戏下的覆盖层、系统级壁纸注入。

## 3. 字段总表（与 0.5.0 的差异）

`Note`：**无变更**（0.6.0 不动条目结构；F2 若做才新增 `State`）。

| Board 字段 | 类型 | 默认 | 状态 | 说明 |
|---|---|---|---|---|
| `Theme` | string | `Dark` | 扩取值 | `Dark\|Light\|System\|Sakura\|Cyber\|Comic\|Custom`；未知按深色 |
| `CustomBackground` | string? | `null` | 新增 | `#RRGGBB`，仅 `Theme=Custom` 使用 |
| `CustomAccent` | string? | `null` | 新增 | `#RRGGBB`，仅 `Theme=Custom` 使用 |
| `ShowTopPanel` | bool | `false` | 新增 | 顶边下拉面板开关 |
| `PanelHeight` | double | `320` | 新增 | 展开高度（DIP），夹取 240–720 |
| `Tone` | double | 现状 | 复用 | 仅在 `Dark/Light/Custom` 下生效；预设主题忽略 |
| `Version` | int | 2 | 不变 | 不加字段不升版本 |

令牌层：`App.xaml` 画刷 7 → 10（新增 `OnAccent`、`Hover`、`Selected`），删除 `App.xaml:32` 的硬编码。

## 4. 旧数据兼容与回滚

**向前（0.5.0 → 0.6.0）**

- 0.5.0 的 `data.json` 直接打开：新增字段缺失时取默认值，`Theme=Dark/Light` 行为不变。
- `System.Text.Json` 反序列化忽略未知成员（`src/Wantodo.Core/JsonBoardStore.cs:45-49`），不因加字段失败。
- 弱化文字两处调色（深色 `#6C7C90→#7C8CA0`、浅色 `#93A1B1→#626F7E`）会带来可见变化，属预期。

**向后（0.6.0 → 0.5.0 回滚）**

- 0.5.0 能打开 0.6.0 的文件：未知字段被忽略，不崩、不丢条目。
- 但 `Theme=Sakura/Cyber/Comic/Custom` 在 0.5.0 回退深色（`src/Wantodo.Core/ThemePalette.cs:84-88`），
  自定义颜色不会写回 0.5.0 保存，**会丢**；回滚前先手抄主题名与两个颜色值。
- `ShowTopPanel` / `PanelHeight` 被忽略，面板自然消失，无副作用。
- 回滚不修改 `Version`，因此无需迁移脚本。
